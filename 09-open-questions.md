# 09. Decision log

Decisions 1 to 25 were taken in review before implementation started. Decisions 26 to 45
were **decided during implementation** of a reference implementation of this plan, which
went from Phase 0 to `v1.0.0` (decision 45 shortly after); they are kept here, rewritten without project-process
details, because they record what the plan got wrong or left open. Decisions 4, 18 and 21
are superseded; decisions 5, 11, 24, 25, 27, 28, 30, 32, 34, 35, 36, 37 and 41 are amended by later
decisions, and each amended row says by which.

## Decisions taken, third round (internal review, 2026-10-16)

| # | Question | Decision | Where applied |
| --- | --- | --- | --- |
| 25 | Versioning of the components | **One module, one version.** The repository publishes a single Go module `github.com/<owner>/powertools-lambda-go` (`<owner>` is a placeholder) with a single tag `vX.Y.Z` for every package; no per-utility modules, no shared `internal` module, no lockstep tagging, no `go.work`. `examples/` is an untagged module with a `replace` to the parent. Accepted cost: the X-Ray SDK is in every consumer's module graph, never in logger-only binaries, enforced by the `deps` CI job. Supersedes 4, 18 and 21. **Amended by decisions 27, 31 and 34:** tags are cut by semantic-release, counting from a seed tag `v0.0.0`; the `deps` job has a direct and a transitive rule, both on production code only. | 01 §2, 04 §1, 05, 06 §5 and §6, 07, 08, 11, README |

## Decided during implementation: pre-implementation analysis

Before Phase 0, the plan was checked line by line against the SDK sources and the
repository tooling. Decision 26 concerned an internal repository template and is omitted
from this public copy; its generic parts (a `Makefile` as the single interface for every
check, an optional build tag on test files) are in 06 §1 and §4.

| # | Question | Decision (decided during implementation) | Where applied |
| --- | --- | --- | --- |
| 27 | Release and versioning | **Releases are cut by semantic-release from conventional commits** on every push to `main`, after the tests and static checks run again. No hand-maintained `CHANGELOG.md`, no release target, nothing tagged or pushed to `main` by hand. After `v1.0.0` a breaking change requires a `/v2` module path. Amends 25. **Amended by decision 34** (timing) and **decision 40** (enforcement). | 06 §6, 07, 11 |
| 28 | Delivery structure | **Phase 1 is the API-freeze point.** It writes the final exported signatures of `logger`, `metrics` and `tracer` that the wrapper uses as documented no-op stubs, adds the X-Ray SDK to `go.mod`, writes the complete `State`, and implements `begin`/`end` in full. Phases 2, 3 and 4 fill in only their own package bodies and add wrapper tests in their own root files (`wrap_logger_test.go`, `wrap_metrics_test.go`, `wrap_tracer_test.go`), so they merge in parallel. Phase 0 creates only `examples/bare`; the coverage gate blocks from Phase 0. Real-AWS jobs wait for an AWS account and do not block the examples. **Amended by decision 45:** the real-AWS jobs are optional. | 06 §1 and §5, 07 |
| 29 | `WrapHandler` contract | **Only for hand-written `lambda.Handler` implementations that own the bytes they return.** `lambda.NewHandler(fn)` is not supported: under `MaxConcurrency` above 1 its `Invoke` returns bytes from a pooled buffer already released, a race that `bytes.Clone` does not fix. `WrapHandler` works on the raw payload and response bytes, passing them as `jsontext.Value` to the correlation-ID options and to response metadata. Other handler shapes use `Wrap` with a one-line closure; no adapter API in v1. Amends 5. | 01 §4.2 and §4.3, 02 §8, README |
| 30 | Trace header source | **The only source is `ctx.Value("x-amzn-trace-id")`**, set by `aws-lambda-go` on every invocation. No `_X_AMZN_TRACE_ID` fallback and no `os.Getenv` per invocation; a missing value means "no trace" for logger and tracer alike. Tests set the key through one helper with the single SA1029 suppression. The parsed header keeps the unparsed trailing fields (`Rest`, a zero-alloc substring), so `tracer.Header` forwards fields such as `Lineage`. **Amended by decision 35:** the parse agrees with the SDK's `header.FromString` on `Root`, `Parent` and `Sampled`. | 01 R2 and §4, 04 §2 and §7, 06 §1 |
| 31 | Tracer nil-safety and helpers | **`*xray.Segment` methods are not nil-safe** (only `Close` is), so the tracer adds nil-safe helpers `AddAnnotation(ctx, key, value) error`, `AddMetadata(ctx, key, value) error` and `InstrumentAWS(apiOptions)`. `end()` nil-checks the segment before every SDK call; the handler segment stays in a local variable of the wrapper, never in `State`; the open-subsegment warning checks after `Close(err)` whether the SDK emitted the handler segment. The import rule covers production code only: test files may import the SDK. Without the wrapper, `Capture` and `CaptureResult` run `fn` untraced when ctx holds no segment and no trace header. `Capture`'s error path adds metadata only; fault and cause come from `Close(err)`. The library never mutates SDK globals, and consumers call `xray.ContextWithConfig` once at init, never per invocation. Amends 24 and 25; refines 20 and 22. | 01 §2, §4 and §7, 04 §3 to §8, 06 §1 and §4, 08 §1 |
| 32 | Metrics API corrections | **`(*Metrics).EmitColdStart(functionName) error` is exported** (`function_name` from the option, then `POWERTOOLS_METRICS_FUNCTION_NAME`, then the argument). `RaiseOnEmptyMetrics` moves to `metrics.Options`; under the wrapper a `Flush` error becomes the invocation error only if the handler succeeded, otherwise it is logged at `WARN`. A batch is empty only if it never held a value, so an auto-flush or a `DeadlineMargin` snapshot that already wrote every value does not make the final `Flush` fail (a documented difference from Python). `FlushSnapshot` writes, then clears metric values and keeps dimensions, metadata and the open state. Key collisions follow Python's merge order (dimensions, metadata, metric values, last wins) in a merge step before encoding, so the encoder never sees duplicate names. A metadata value that fails to marshal is dropped with one `WARN` per batch. **Amended by decision 35:** `Flush` returns only sentinels. | 01 §4 and §6, 03 §2 to §8, 07 Phase 3 |
| 33 | Logger and wrapper corrections | **The handler follows slog's `commonHandler` structure** (top-level attrs, grouped prefix, trailing empty groups opened only when a record attr renders). Package functions `Trace`…`Fatal` build the record themselves so `location` names the caller. Duplicate keys are emitted as slog does, and every decoder allows duplicate names and invalid UTF-8. `ReplaceAttr` never sees built-in keys, Lambda keys or `AppendKeys` attrs. `KindAny` values that fail to marshal render as `"!ERROR:<err>"`, like `slog.JSONHandler`; the line is never dropped. `LevelSilent` wins over sampling; `RefreshSampleRate` is removed (sampling needs the wrapper). `FlushOnErrorLog` becomes `*bool` and `BufferAtLevel` a `slog.Leveler`, so zero values stay usable. One shared stdout writer is used when a utility's `Writer` is nil. `logger.FromContext` falls back to `slog.Default()`. `internal/env` is folded into `internal/lambdaenv`; `internal/jsonpath`, `internal/benchutil` and `internal/testsupport` join the layout. The tracer's per-value metadata guard becomes a per-invocation budget counted as escaped size, because the SDK streams by subsegment count, not by size, so an oversized document is dropped whole. Amends 11 and 24. | 01 §2 to §6, 02, 03 §2, 04 §1, §2 and §5, 05 §3 and §4, 06 §1 |

## Decided during implementation: releases, Phase 1 and the utilities

| # | Question | Decision (decided during implementation) | Where applied |
| --- | --- | --- | --- |
| 34 | Release timing and v0 versions | **Release from the start, in v0, and cut `v1.0.0` once at the end.** A seed tag `v0.0.0` makes semantic-release count from v0; the release workflow lands right after Phase 0. Each phase that merges `feat` commits releases a v0 minor; fixes give patches. During v0 an exported API may change, written as `feat` or `fix`, never as a breaking change. After the API review, one commit with a `BREAKING CHANGE` footer cuts `v1.0.0`; v0 to v1 needs no `/v2` path. README install examples use `@latest`. Amends the timing of 27. | 06 §6, 07, 08 §3, 11, README |
| 35 | Phase 1 implementation choices | (1) **No init-time env snapshot**: constructors read the environment and cache it, so nothing reads it per invocation and tests can `t.Setenv` before constructing. `InLambda` is `AWS_LAMBDA_FUNCTION_NAME` non-empty; `AWS_LAMBDA_MAX_CONCURRENCY` is read by `aws-lambda-go` only. (2) **Trace header parsing** agrees with the SDK on `Root`, `Parent` and `Sampled` (any position, a later duplicate wins, `Sampled` true only for `Sampled=1`); `Rest` is the trailing run of other fields, an accepted divergence because Lambda sends extra fields last. (3) **The margin timer** is not armed when `remaining - margin <= 0`. (4) **`RemainingTime`** without a deadline returns the maximum `time.Duration` (no limit), so `context.WithTimeout(ctx, RemainingTime(ctx) - margin)` works in local runs and tests; with a deadline it is clamped at 0. (5) **Handler name** under `WrapHandler` is the dynamic type of `h`; `Options.HandlerName` replaces the derived name and `"## "` is always prefixed. (6) **Wrapper edge cases**: a malformed `CorrelationIDPath` is reported once at `WARN` at wrap time and disables the extraction; a panic in `CorrelationIDFunc` is not recovered; a panic in the event's marshal method is recovered and logged. (7) **`Flush` returns only sentinels**, never an I/O error, and any `Flush` error follows decision 32's rule. (8) **`go.mod`**: an explicit indirect floor on `golang.org/x/net`, because the version the X-Ray SDK requires fails `govulncheck`; removed once an SDK release requires a fixed version. Amends 24, 30 and 32. **Amended by decision 42** (`LogEvent`). | 01 §1 to §7, 02 §1, §8 and §9, 03, 04 §1 to §5, 05, 07 Phase 1, 08 §1 |
| 36 | Metrics behaviour | An invalid namespace returns `ErrNamespaceMissing` from `New` and `Single.Emit`. `service` is the first default dimension, so it is in every set, every `Single` and the cold-start blob. An auto-flush without a namespace drops its values and `Add` returns `ErrNamespaceMissing`; write errors are logged at `DEBUG` once per batch and never returned by batch paths. Metadata keys `""`, `"_aws"` and invalid UTF-8 are dropped with the one metadata `WARN`. `Len` counts the distinct definitions held and not yet written. Metric names are 1 to 255 printable ASCII bytes, not blank, not `_aws`. At most 29 dimension keys per set, `service` included. Zero values of `Metrics`, `Batch` and `Single` are inert. **Amended by decision 44** (the `New` error is kept). | 03 §1 to §8 |
| 37 | Examples and real-AWS delivery | (a) The `size` job is blocking from its creation: `examples/hello` adds less than 1 MiB over `examples/bare`, both built in the same run (no committed baseline), and `hello` does not reach the X-Ray SDK (`go list -deps` and `go version -m`). (b) SAM templates deploy the prebuilt `bootstrap`, so the deployed binary is the measured one. (c) The integration harness is Go tests behind `//go:build integration`; without its variables or credentials it skips, unless a "required" variable is set, and a pull-request step proves the skip. (d) The nightly `integration` and `measure` jobs are merged present and skipped until repository variables name an AWS role and region; credentials come from OIDC, and no step relies on a session longer than one hour. (e) The benchmark is two binaries, plain and wrapped, so the init comparison includes linking. (f) `govulncheck` covers the library module only; the never-released `examples` module is covered by dependency updates. (g) SAM templates are linted with `cfn-lint`, limited by a path filter. (h) Example-only changes use `chore(examples)` or `test(examples)`, because the release rules have no scope filter. **Amended by decision 45** (the real-AWS jobs are optional). | 05 §5 and §6, 06 §1, §4 and §5, 07 Phase 5 |

## Decided during implementation: Phase 6 and the API review

| # | Question | Decision (decided during implementation) | Where applied |
| --- | --- | --- | --- |
| 38 | Build tag of the example files | **`example_test.go` files carry no build tag** when the repository tags its test files: `go doc -ex` does not list examples from tagged files, and `go doc` has no `-tags` flag. A doc check proves for each public package that `go doc -ex` lists at least one example, that an untagged `go vet` compiles the example files on their own (so an example cannot use a helper of a tagged test file), and that no stub sentence from the API-freeze phase remains. | 05 §5, 06 §1, §4 and §7, 08 §3, 10 |
| 39 | Bench gate | **The bench job blocks and is required.** One job on one runner checks out the merge base and the head and runs the gated subset of both, interleaved, with `-count 10 -benchtime 300ms -cpu 1`; `benchstat -format csv` feeds a gate script (benchstat always exits 0), which a local target runs too. Any `allocs/op` or `B/op` increase at p < 0.05 fails; `ns/op` fails above 25 % at p < 0.05 (the threshold 05 §6 left open between 20 and 25 %, reviewed after enough recorded runs). Benchmarks on one side only are `new` or `removed`, never gated; `b.ReportMetric` units are informational. A reviewed accept-list turns a listed failing benchmark into `accepted`; a stale entry is reported. No committed baseline is a gate input; profiles and bench files are uploaded as job artifacts. | 05 §5 and §6, 06 §5, 10 |
| 40 | Release commit and breaking-change guard | **A bang header is banned everywhere**: the angular parser has no `!` in its header pattern, so such a commit releases nothing and leaves the release notes. Its note pattern is case-insensitive and applies to every line of every commit, merge commits included, so nothing starts a line with the breaking-change phrase except the release commit. A guard script scans the pull-request range and the PR title (a squash merge can make the title the header), and, before every release, the range since the highest reachable version tag. The `v1.0.0` commit is accepted once, while no v1 tag exists; after it, a note is accepted only from a commit whose own `go.mod` declares the next `/vN` path. A note commit reverted in the same range, or an allow-listed full SHA, is cleared. The release pull request is merged with a merge commit, not squashed. Recovery when the guard holds `main`: revert the commit that carries the marker (not the merge commit) before any other releasing change; disabling the guard is not a recovery. Amends 27 and 34 (enforcement, not timing). | 06 §5 and §6, 07 |
| 41 | `v1.0.0` and the real-AWS checks | **`v1.0.0` is cut without Phase 5b.** Cutting the release needs no AWS account. The CloudWatch and X-Ray acceptances of Phases 3 and 4 and the Lambda-level measurements of 05 §5 become post-v1 checks; a failure there is a v1 `fix`. Amends 34. **Amended by decision 45:** Phase 5b is a configuration step; the checks are recorded whenever the optional jobs are enabled. | 05 §5, 07 |
| 42 | `Options.LogEvent` | **`powertools.Options.LogEvent` is a `*bool`.** Nil means `POWERTOOLS_LOGGER_LOG_EVENT`; `new(true)` or `new(false)` wins over the variable, so `new(false)` switches a truthy variable off. The plain `bool` could only switch the feature on, and it was the only environment-backed option that was not tri-state. Ships as a `feat` during v0. Amends 35. | 01 §3 and §4, 02 §8, 08 §4, README |
| 43 | Metric storage resolution | **`metrics.Resolution`, `Standard` and `High` are unexported.** No exported function or method took or returned the type: the resolution is chosen by the method (`Batch.Add`, `Batch.AddHighResolution`, `Single.HighResolution`), so the identifiers were surface nobody could use that `v1.0.0` would have frozen. The output is unchanged. Ships as a `fix` during v0. | 03 §1, §2 and §4, 08 §4 |
| 44 | API review items kept as they are | (1) `metrics.New` returns an error while `logger.New` and `tracer.New` do not: metrics validates at construction because an invalid namespace or dimension would make every later blob invalid; the logger falls back with one `WARN`, and the tracer has nothing that can fail. (2) The end-of-handler helper stays exported as documented wrapper plumbing: it takes an `*xray.Segment`, and `internal/...` must never reach the SDK. (3) `logger.Handler`, `metrics.Batch` and `metrics.Single` stopped being comparable after the stubs got their bodies; only pointers are handed out, and no doc promised comparing values. (4) The three `FromContext` functions keep one name, `(*XRayLogger).Log` keeps the SDK's signature, and `RemainingTime` keeps returning the maximum duration without a deadline. Amends 36. | 08 §4 |
| 45 | Docs-only changes and the optional AWS jobs | **(a) Docs-only changes skip the code checks and never reach the release workflow.** A first CI job lists the files the pull request changes; the lint, library-check, build, size and bench jobs run only when some file is neither Markdown nor under `docs/`, and a diff that cannot be computed runs every job. GitHub counts a skipped job as passed for a required check, so a docs-only pull request stays mergeable. A title or description edit re-runs only the checks that read the title (the breaking-change guard). The release workflow ignores pushes to `main` that touch only Markdown and `docs/`; a `feat` or `fix` commit that touches only those files is not lost, it releases with the next push that changes code, because semantic-release reads every commit since the last tag. **(b) The real-AWS jobs are optional.** The nightly `integration` and `measure` jobs and the integration harness stay in the repository and run only when repository variables name an AWS role and region; otherwise GitHub reports them as skipped. Phase 5b is a configuration step, not code (set the variables, run the jobs, record the results), with no separate provisioning task: the CloudWatch and X-Ray acceptances and the Lambda-level measurements of decision 41 are recorded when the jobs are enabled, and a failure there is a v1 `fix`. Amends 28, 37 and 41. | 06 §5, 07 Phase 5 |
